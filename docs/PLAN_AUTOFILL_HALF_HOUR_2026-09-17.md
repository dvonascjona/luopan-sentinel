# ASK JUNIOR 自动填表改造计划

> 北京时间：2026-09-17
> 状态：待 dv 确认后实施（`20:30`、`21:00` 已于 2026-09-17 按当前快照手工回填）

## 目标与边界

1. 每 30 分钟写一次 ASK JUNIOR 表，使 `20:00`、`20:30` 等行都有各自快照。
2. 填表读取、字段校验、行匹配或飞书写入失败时，向既有数据分析群发出真实错误原因。
3. 退役旧杭州填表脚本与历史日志，避免新旧流程混淆；不删除任何数据归档、Cookie 或现行 ASK 脚本。

> 手工回填记录：为支持指定时间行的受控补数，`auto_fill_ask_junior_sheet.js` 接受 `ASK_TARGET_TIME=HH:00|HH:30`。该参数仅用于手工补数；自动 cron 仍使用真实快照对应的默认整点行。

## 实施设计

| 项 | 做法 | 验收 |
|---|---|---|
| 半小时采样 | 新增 30 分钟的轻量大屏/清洗触发，填表脚本依据真实采集时刻匹配 `HH:00` 或 `HH:30` 行；不复用整点累计快照冒充半小时新数据。 | 连续两次执行分别读回 `20:00`、`20:30` 的 B:L。 |
| 错误告警 | 新增 `run_ask_autofill.sh` 包装器：保留 Node 原始 stderr 到 `/tmp/ask_autofill.log`，失败时由 bot 发群消息，含北京时间、退出码和经长度限制后的真实错误。成功不刷屏。 | 用受控的缺字段测试数据运行，群内收到 `❌ ASK 自动填表失败`；正常真实数据执行无告警。 |
| 旧流程退役 | 删除服务器 `/opt/douyin-fetcher/auto_fill_hangzhou_sheet.js` 与其三个 `.bak.*`；清空旧 `/tmp/autofill.log`，新流程独占 `/tmp/ask_autofill.log`。保留当前 ASK 脚本和其回滚备份。 | `ls auto_fill_hangzhou*` 无结果；`crontab -l` 只引用 ASK 包装器；新日志有可辨识的运行记录。 |

## 调度设计

- 整点采集继续负责 `HH:00` 数据。
- 新增 `HH:30` 的 Route B/清洗后填表链路，采集完成再填，避免把上一轮快照错写到半小时行。
- 使用独立 `flock /tmp/ask_autofill.lock`，禁止与手工执行或相邻轮次重叠。

## 风险与回滚

- 腾讯云内存有限，新增半小时采集必须复用现有 Route B HTTP 路径，不新增并发 CloakBrowser。
- 部署前备份 cron 与被删除的旧杭州脚本；代码在本地仓库 commit+push 后再部署。
- 回滚：恢复 cron 备份、还原旧脚本备份，并执行 `git revert <实施提交>`。

## 变更预期

- 腾讯云运行骨架：上述脚本、cron、日志路径；删除的仅限明确列出的旧杭州脚本和旧运行日志。
